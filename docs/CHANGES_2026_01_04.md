## Part 2: Critical Data Quality Issues Discovered

### 2.1 Mixed Data in Training Folder

The folder `data/anemia_crops_split` contained:

| Type | Count | Description |
|------|-------|-------------|
| Proper crops | 244 | Rectangular ~256×97 px (conjunctiva only) |
| Uncropped images | 61 | Square 256×256 px (full eye, resized) |
| **Total** | 305 | 20% contamination |

**Action Taken:** Removed all 61 square (256×256) images.

**Remaining clean data:**
- Train: 97 anemic + 96 nonanemic = 193 images
- Val: 23 anemic + 28 nonanemic = 51 images

### 2.2 Flawed Original Cropping Method

The existing crops were created using `scripts/pseudomask_conj.py` which uses **red-color detection**:

```python
a_th = int(np.clip(np.median(a) + a_delta, 120, 200))
red = ((a >= a_th) & (L >= 30) & (L <= 240))
```

**Critical Flaw:** This algorithm looks for RED pixels to find the conjunctiva. Anemic patients have PALE conjunctiva with little red - so the cropper fails on the very people the app is designed to detect.

### 2.3 User Reports More Raw Images Remain

Despite removing 256×256 images, user identified that many "crops" in the folder are still problematic - possibly poorly cropped or raw images that aren't perfect squares.

## Part 6: Key Insights

1. **SimpleCNN vs ResNet18:** Neither is reliable with current data. The issue is data quality, not model architecture.

2. **Why ResNet18 predicted backwards:** The flawed red-detection cropper worked better on healthy (red) eyes than anemic (pale) eyes. So the "anemic" training folder likely contains better-quality crops of healthy-looking conjunctiva.

3. **Manual crop is the solution:** Using the app's UI ensures:
   - Consistent crop region across all images
   - Works on both pale and red conjunctiva
   - Training data matches production usage
